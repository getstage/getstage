 # Stage Reliability Recovery Plan — 2026-06-26

  Rule: A checkbox is only done when the product behavior is actually
  verified, not when code “looks like it should work”.

  ## 0. Implementation Discipline

  ### Problem

  There are many connected bugs. If we fix them with one giant messy branch,
  we risk creating more hidden failures.

  ### Task

  - [ ] Keep fixes small and reviewable.
  - [ ] Prefer existing helpers/hooks/mutations before adding new
    abstractions.

  - [ ] Do not add speculative systems.
  - [ ] Keep destructive actions backend-safe, not only UI-safe.
  - [ ] Every user-facing error must be calm and actionable.
  - [ ] Raw technical errors stay in logs, not UI.
  - [ ] Every fix needs a manual acceptance test.

  ### Acceptance Test

  A reviewer can open the plan and see exactly what was fixed, what remains
  open, and how to test each item.

  ## 1. Research / Refero Image Ghost Data

  ### Problem

  Research UI showed Refero image URLs that no longer existed in R2. That
  means the UI displayed ghost data.

  ### Current Status

  - [x] Rerun cleanup happens at run start.
  - [x] Cleanup no longer runs after successful generation.
  - [x] Old research artifacts are cleared before new output is saved.
  - [x] Old strategy artifacts are cleared when research rerun invalidates
    them.

  - [ ] Not fully proven that saved artifact JSON can never reference missing
    R2 keys.

  ### Tasks

  - [ ] Verify new Refero images are only written into the artifact after
    upload succeeds.

  - [ ] If an image upload fails, do not save a ready artifact pointing to
    that missing image.

  - [ ] If partial image persistence fails, mark the run failed/degraded
    instead of silently succeeding.

  - [ ] Add missing-image UI fallback: Image unavailable.
  - [ ] Add a diagnostic/manual script path to check artifact image URLs
    against R2 keys.

  ### Acceptance Test

  Rerun research twice on the same project. Reload. Every displayed Refero
  imageUrl exists in R2, and no old deleted image URL appears.

  ## 6. DirectionPreviewImage / useEffect

  ### Problem

  The fallback image code is confusing and may duplicate existing image logic.

  ### Why It Exists

  sourceIndex tries thumbnail → image → imageUrl → sourceUrl.
  The useEffect resets the fallback index when the item changes, so one broken
  image does not make the next image start from the wrong fallback.

  ### Tasks

  - [ ] Check if an existing image fallback component already exists.
  - [ ] If yes, replace DirectionPreviewImage with existing helper.
  - [ ] If no, keep it but rename/comment minimally so it is understandable.
  - [ ] Include sourceUrl in reset dependencies if it remains.
  - [ ] Avoid adding more fallback helpers.

  ### Acceptance Test

  One broken image falls back correctly. Switching to another image resets to
  its first valid source.
