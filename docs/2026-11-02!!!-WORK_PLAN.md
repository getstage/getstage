## Phase 4 — MCP

Users connect their own AI tool (Claude, Claude Code, Cursor, Codex, ChatGPT) to one URL and sign in with their Stage account once. The AI then reads and saves their Stage projects. Estimate: first usable version ~1 week, complete ~2–3 weeks.

Branch: `feat/mcp` (worktree `~/stage_mvp-mcp`). Status per item: **Built** = in code and committed · **Testing** = deployed to testing · **Tested** = checked by Werner · **Prod** = live.

### Decisions

| Decision | Choice | Why |
|---|---|---|
| Where the server runs | Separate Cloudflare Worker `apps/mcp-server` at `mcp.getstage.co` (testing: `mcp-testing.getstage.co`) | Remote MCP over HTTP works in every tool; no install for users |
| Login | Stage itself is the sign-in: the server sends the user to the web app page `/connect-ai` | Reuses the existing Stage login (Convex Auth); no second account |
| What the AI uses to act as the user | One MCP key per connection, same table as API keys (`apiKeys`, `kind: "mcp"`) | Reuses API key checks and rate limits; revoking the key disconnects the tool |
| How tools reach Stage data | Existing Stage API `/api/v1/...` with that key | No second backend; tools stay small |
| Who can connect | Studio and Agency (`pro`, `team`) — Werner, 2026-11-05 ("b") | Checked on every call, so a downgrade disconnects |
| Server type | Stateless (`createMcpHandler`, no Durable Object) | Nothing to keep between calls; data lives in Stage |

### How connecting works

1. The user adds `https://mcp.getstage.co/mcp` in their AI tool.
2. The tool registers itself and opens `mcp.getstage.co/authorize` in the browser.
3. The MCP server makes a secret (PKCE verifier) and sends the browser to `getstage.co/connect-ai` with the tool's name, where access goes, and a hash of the secret. The request is bound to this browser with a cookie.
4. On `/connect-ai` the signed-in user sees "Allow Claude to use Stage?" (app name, where access goes, a warning for apps on the computer) and clicks **Allow** or **Cancel**. Not signed in → Stage login first, then back to this page.
5. **Allow** creates a one-time code in Convex (5 minutes, Studio/Agency only) and sends the browser to `mcp.getstage.co/callback`.
6. The MCP server swaps the code plus its secret at Convex `POST /mcp/connect/token`. Convex checks the code is unused, not expired and matches the secret, marks it used, and creates the MCP key `MCP · <tool name>`.
7. The MCP server stores the key encrypted with the tool's login and returns the tool to where it started. Every tool call then uses that key.

A stolen code is useless without the secret; a code works once even when the secret is wrong; the callback only works in the browser that started.
