Werner created a **Websites** project. The header shows **Websites**. Research still ran **Refero**, wrote **Web apps** into the snapshot, and labeled UI Patterns **Analysed with Refero**.

## The actual break (one missing field)

1. Header uses `desktop` / `projects.getById` → `project.type` → label **Websites**.
2. Engine calls Convex `projectAi:getResearchInput`.
3. **Production Convex (`prod-v0.2.36`) does not return `projectCategory`.** That field exists only in the **uncommitted local** handler.
4. Engine deserializes a missing field as `""`.
5. `ProjectCategory::from_project_type("")` silently maps unknown to **Web apps**.
6. Workflow: only `web-design` uses Details. Everything else uses Refero.
7. Prompt says `Project category: Web apps` and `from Refero`.
8. Codex writes snapshot Category **Web apps**.
9. UI Patterns copy is hardcoded to Refero anyway.

**Files**

- `packages/data-ops/convex/lib/projectAi/handlers/context.ts` — local add of `projectCategory: project.type`; **not on the Convex deployment the desktop is using**
- `apps/stage-engine/src/convex_store/research_repository.rs` — `#[serde(default)]` on `project_category`
- `apps/stage-engine/src/models/research.rs` — `_ => WebApps` fallback
- `apps/stage-engine/src/research/workflow.rs` — Details only if `ProjectCategory::Websites`

Details never ran on this project. Refero ran because the engine thought it was a web app.

## Components that are wrong or half-wired

### 1. Research routing — broken for Websites

- **Intended:** Websites → Details.so. Web apps / iOS → Refero.
- **What happened:** Websites → Refero.
- **Cause:** category never arrives from live Convex; fallback is Web apps.

### 2. Silent fallback — hides the bug

`from_project_type` must not turn missing/unknown into Web apps. That is why a Websites project looked like a successful Refero run instead of failing closed.

### 3. Convex deploy gap — Details cannot work on this deployment yet

Uncommitted, not deployed:

- `projectCategory` on `getResearchInput` / strategy input
- `appSecrets:getDetailsMcpToken`

Even after routing is fixed, Details token fetch needs this query live and `DETAILS_MCP_TOKEN` in Convex env.

### 4. UI Patterns badge — always Refero

`apps/user-application/src/components/project/tabs/research/UiPatterns.tsx` hardcodes **Analysed with Refero**. A real Details run would still show Refero.

### 5. Company Snapshot category — model copy, not the project type

Snapshot **Category** is generated by Codex from the prompt. It is not the header label. Once the prompt says Web apps, the table says Web apps. Two labels, one lie.

### 6. Refero output on this run — wrong job, not a rewritten Refero client

`apps/stage-engine/src/refero/` was **not** edited.

What looked “destroyed”:

- A **marketing website** brief was sent through **app** Refero searches (onboarding / login / dashboard / checkout).
- Hits like Miro “Set up your account” are what that path returns.
- Refero queries still key off industry (`E-commerce`) + brief snippets. They were never meant to replace Details for marketing sites.

For a real **Web apps** / **iOS** project, Refero is the same client as `prod-v0.2.36`. This screenshot is a Websites project on the app path.

### 7. Research prompt — category + provider strings

`apps/stage-engine/src/research/prompt.rs` now injects project category and “Details” vs “Refero”. On this run that amplified the wrong category (Web apps + Refero) into Codex output.

### 8. Details module — extra surface, not used here

Local only:

- `apps/stage-engine/src/details/` (parse + service)
- Workflow branch for Websites
- Config `DETAILS_MCP_*`

This project never entered that branch.

### 9. Style Guide / Strategy category plumbing — same missing field

Local changes pass `projectCategory` into strategy + style guide. Same Convex gap: live functions may still omit it, so those stages can also default to Web apps conventions.

### 10. Create-flow lock vs leftover 9-type tables

Create UI locks to 3 types (`web-design` / `web-app` / `app-design`). `PROJECT_TYPES` in `apps/user-application/src/lib/constants.ts` still lists the old 9. Header labels still know all 9. Create itself is not why this run used Refero.

## What was not rewritten

The damage on this Websites project is **wrong provider**, not a new Refero algorithm.
